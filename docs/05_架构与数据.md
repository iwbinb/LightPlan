# 05 · 架构、数据与安全恢复

## 1. 技术选择

SwiftUI原生（最低iOS17设计基线），MapKit地点/底图，CoreLocation可选定位，App Store下载前付费（无运行时内购模块），UserNotifications本地提醒，WidgetKit小/中组件。Foundation-only `LightPlanCore`与UI分离，Swift Package没有外部依赖。XcodeGen是开发工具，不进入App运行时。[S03–S07,S13]

构建与提交应使用当前受支持的Xcode/SDK；2026-04-28起Apple要求上传使用Xcode26或更新及相应SDK，检索时官方提交页已说明Xcode27。[S02] iOS17最低运行版本并不意味着可以用旧SDK提交。Codex必须记录本机实际版本，不假定某安装路径存在。

天文模型以 `docs/04_天文与时间规范.md` 为当前说明：太阳采用VSOP87D及相关视位置修正，月亮采用独立的轨道元素/周期扰动近似；不再把旧简化NOAA式太阳模型当作当前实现。有限样本验证与现场精度边界按该规格及科学报告记录。

不采用WebView套壳，不需要Electron/Three.js/服务器渲染。Cloudflare只在需要正式隐私、帮助与展示站时使用静态部署；不为天文计算调用Workers。

## 2. 模块图

```
SwiftUI screens ── AppState / observable models
                 ├─ LightPlanCore (astronomy, LocalDay, plan, archive)
                 ├─ MapKit / optional CoreLocation
                 ├─ Local repository → Application Support (atomic)
                 ├─ ReminderService → UserNotifications
                 └─ AppGroup sanitized snapshot → WidgetKit
```

UI只派发意图与展示状态；耗时全日计算在后台任务完成，保留请求ID丢弃过时响应。时间轴单个位置更新不能触发全天重新采样。缓存key至少含坐标、目的地时区、民用日、算法版本，不用“城市名”当唯一key。

## 3. 已提供模型

- Coordinate：经纬有限值校验；解码也验证。
- Place：UUID、name、coordinate、timeZoneID、isExample；时区不允许不存在。
- DaySummary：目的地日start/end、事件数组、窗口、horizonState；派生数据可重建。
- ShootPlan：稳定UUID、title、Place快照、日期、目标、准备/提醒分钟、可选notes（最多2000字符）、collectionName（最多60字符）、completedAt（有限绝对时刻）、created/updated；构图目标额外保存天体、主体坐标、偏移和精确对齐时刻，以及可选搜索条件constraints和相机配置cameraFraming。项目名/完成状态缺失时分别视为未分组/未完成；不把历史时间已过等同于用户已完成。
- OpportunityConstraints：对齐误差、天体高度范围、可选太阳高度范围与moonIlluminationRange；它们是几何搜索条件，不代表天气或遮挡可见性。UI保留低空、太阳高度和全部候选预设，支持自定义；条件无结果须如实为空，不自动放宽。范围以lowerBound/upperBound显式编码，先验证再构造ClosedRange，防止反序边界触发前置条件崩溃。高度范围要求有限、−90…90且下界严格小于上界；月亮照明使用0…1比例，下界可等于上界，但零宽条件没有正时长拍摄窗口。解码缺失月照明字段为nil；构图计划保存条件，改日期时继续使用。
- CameraFraming：35mm等效焦距14–1200mm、landscape/portrait画幅、参考仰角−30°…60°；解码同样验证范围和有限值。36 × 24mm等效画幅的针孔投影以相机右/上/前轴计算天体中心与视圆轮廓，横竖转换交换画幅尺寸，保持水平线定义。参考仰角不是实测建筑高度；不编码地形、实景、镜头校准或折射。
- OpportunityWindow / OpportunityWindowSearchResult：派生结果包括一段连续DateInterval、窗内最佳AlignmentCandidate、该时刻月照明，以及实际搜索dayCount、整段搜索interval和isTruncated。结果窗口不跨民用日合并；持久化保存选定最佳点与条件，不存整批搜索缓存。
- PlanLibrary：按计划快照派生目的地民用日、当前是否已过/是否无事件；当天普通太阳计划需要真实事件时刻，构图计划用保存的绝对时刻。按多关键词搜索title/place/notes/collectionName，按全部/即将开始/已完成/过去筛选，再按项目组织。
- FieldSessionStatus：基于保存的到场/拍摄绝对时刻和completedAt推导到场前、准备、拍摄时刻到达、已过、完成；状态不依赖手机时区，也不宣称正在实时观测天体。
- PlanFieldBrief：由同一计划快照与日汇总导出到场/拍摄绝对时刻和Apple地图观察点链接；UI按目的地时区生成可分享文字，包含构图信息和可选备注。
- Archive：继续写入schemaVersion=2，兼容读取schemaVersion=1；ISO8601日期、尺寸/条目上限、重复ID检查。旧版App应拒绝不支持的schema，不能把构图数据误读成普通日落计划。此次相机配置、月照明、项目名和完成时刻是v2的可选扩展，新版本读取缺失这些字段的旧v1/v2档案。该向后读取兼容不代表旧App往返写回时能保留其不认识的新字段，不能承诺降级无损。

提醒执行状态与用户意图分离：用户设定“开提醒”不表示系统已成功安排。详情页读取系统通知权限与排队触发时间，仅在计划ID和触发时间匹配时显示已安排；备份包含提醒意图，不包含系统授权或已经送达的断言。构图计划的到场、提醒和地图恢复共同使用保存的对齐时刻。已完成计划即使带旧提醒意图也不能重新安排；标记完成先原子保存，再取消通知。恢复待拍及复制都清除提醒意图，复制还清除completedAt并生成新ID。

## 4. 存储与事务

计划/收藏写入Application Support文件，用原子替换和系统数据保护。设置仅存轻量语言/选点。不存储付款布尔值，也不通过开发解锁开关开放功能；付费下载应用的功能不依赖运行时购买状态。共享组只放Widget必需地点、时区、语言与可用状态，不复制整份历史计划。

当前基础代码保存/删除已有回滚策略；文件损坏后锁定写入，并可原样导出损坏文件。正式版实现导入时：预检→冲突预览→用户确认→生成回滚备份→原子写→重新加载验证→只在成功后切换内存。失败不污染内存和磁盘。

存储文件沿用既有路径，避免升级时漏读旧数据。首次将旧schema存档写成v2前，保留独立的旧schema原件；之后普通写入不会覆盖这份迁移备份。只读取旧存档不会写盘。导入旧备份后再次导出使用v2。

编辑构图计划时，修改日期、天体或偏移会重新计算对齐时刻；观察点与主体使用计划内的不可变快照。未找到有效结果时禁止保存；不把结果偷偷退回日落。所有安装后的用户均可阅读、编辑、导出、回到原构图地图及管理提醒；数据不依赖付款状态。

建议默认档案限5MB、每类10,000条，避免意外内存峰值。限制是产品安全值，不是性能已测结论。大文件显示拒绝原因，不尝试无限解码。

## 5. 导入导出

导出是JSON便携备份，不上传到我们服务器；通过系统分享面板由用户自己选目的地。系统分享可能发往第三方，这是用户触发行为，隐私说明要准确。

导入支持当前schema；未来schema明确拒绝，旧schema经迁移后保留备份。重复ID不自动覆盖；默认保留本地并可选择导入为副本。名称、经纬、时区、日期、枚举、分钟范围逐项校验，不接受非有限浮点、未知事件、过大字符串或任意文件路径。

首次导入成功后不自动请求定位、不恢复过期提醒。让用户选择要启用的未来计划，统一说明系统权限。

## 6. 异步与并发

MainActor负责UI，Core纯值Sendable。各搜索请求带取消与序列号，旧结果不得覆盖新查询。切换地点日期时保留当前选点直到新数据可用；错误返回解释并允许重试。

当前源码的实际构建与测试证据以STATUS.md及对应报告为准。Mac阶段重点检查CoreLocation代理隔离、MapKit对象跨actor、计算取消/过时结果、Widget扩展API安全与ResourceBundle。必要时缩窄隔离边界，不能滥用`@unchecked Sendable`消除警告。

### 连续窗口与界面请求

`CompositionPlanner.opportunityWindows/Async`接收1–90个目的地民用日，使用当地Gregorian Calendar逐日推进，保留23/25小时及半小时DST日；超出1900…2100支持范围时停止并返回实际dayCount与结束边界。核心输出limit为1–360，当前UI取60；`isTruncated`只表示匹配数超过limit，范围末端缩短由dayCount与interval说明。旧`opportunities/Async`保留每日最佳点返回结构，天数/限额上限扩到90。

先分别隔离天体高度、太阳高度、实际时刻月亮照明和方位误差的有效区间，再求交，并在每个独立区间内优化最佳点。不是“先取全天最佳点，再过滤”来冒充连续窗口；同一天可以有多段。粗采样之外细化局部极值和边界，保留短暂近相切机会；数值根精化不是全球连续精度证明，更不含大气与遮挡保证。零宽等式条件不虚构可持续时间。

`OpportunitySearchView`持有不可变的观察点/主体快照，搜索配置与选项草稿分开；应用配置才重算，取消草稿不改旧查询。后台工作传递取消信号，配置身份及generation共同阻止旧结果覆盖。选中回传结果时仍检查配置身份。预设标签用横向完整文字按钮；按日期排序是在已经按匹配质量限额的结果内排序，数量截断说明不能省略。

现场倒计时用独立`TimelineView`每秒更新显示，全天星历与简报计算留在卡片外，不因每个秒跳重复计算。当前原生设备、语言和大字体矩阵仍按最终源码验收，结果由`STATUS.md`及本轮最终报告记录；本节不预先宣称全部通过。

## 7. 配置

候选Bundle ID：com.arenovo.lightplan；App Group：group.com.arenovo.lightplan。收费方式为paid_upfront，不配置内购ID。以上是候选，不代表已在开发者账号注册。`ios/Config/Local.xcconfig`覆盖真实ID/Team；不提交个人签名文件。

App Group名称从Info.plist由同一build setting注入，app与widget不能各自写死不同值。正式版要核验实际entitlements而不只看YAML。支持网址/隐私网址/运营主体及应用定价状态在release config集中审核。

## 8. 不做的后台行为

无位置持续采集、无背景网络轮询、无AI云调用、无强制账号、无远程同步依赖。Apple地图/地理编码，以及由App Store处理的下载/更新仍可能联网，所以不能宣传“整个App没有任何网络数据流”。日志不得记录精确地点、用户计划正文、备注或账号凭据。
