# 逐屏截图验收：禁止仅凭描述签收

## 证据来源必须明确

A：`design/reference`是ImageGen目标，不是产品截图。B：`design/v3-reference`为本次Chromium真实渲染，证明HTML/CSS/JS布局；不证明iOS。C：`tests/reports/v3/native-*`应由Codex在Mac生成，才是原生模拟器截图。真机照片/录屏是第四类，不能与C混称。

## Codex执行顺序

1. 重跑核心与结构验证；用XcodeGen生成工程。
2. 完成所有SwiftUI/MapKit/SDK编译错误，不允许改成WebView。
3. 运行`bash scripts/v3/capture_native.sh phone`；再执行`expanded`和实际可用时的`duo`。
4. 从xcresult提取九语首页、地图、计划详情。浅色/深色、最大字体、无地图网络、地点权限拒绝另补截图。
5. 对照`design/reference`的摄影气质，再对照`design/v3-reference`的具体结构，用本包compare_screens.py输出并排、叠图、差异图与说明。字体/卫星纹理差异不能遮掩模块丢失。
6. 逐屏修复，重新截图。只有原生截图与当前源码版本一致，才可在视觉门槛记录reviewer和evidence。

## 必须满足

首页：原创场景不是渐变；标题可读；4卡真实时段；时间轴真实曲线；模块边距与图片比例接近参考；不存在遮罩挡住数据。

地图：真实MapKit底图有来源署名；当前方向/升落方向/黄金扇区正确；地图可拖动缩放；浮动面板不遮挡关键系统控件；不以浏览器方向图通过此门槛。

计划：照片Header、实时标题、日期与目的地时区；节点色彩与事件一致；修改标题/日期/提醒后数据和界面真实变化；CTA可操作；没有“假开关”。

宽屏：侧栏是信息密度提升而非把手机版拉宽；地图、时间轴、侧栏同步；折叠前后的选中时间、地点、地图状态连续。

九语/辅助功能：时间不能省略成“…”；过长文字转行；日期/时间符合设置；用户改变语言后没有一半旧语言；照片文字在高对比和大字体下可读。

## 对比脚本不是自动质量证明

compare_screens.py的像素差只作诊断。浏览器与原生字体、Tab Bar、地图纹理不同，单一分数不能代表UI质量。脚本不写passed门槛，不允许用宽大遮罩把整张地图/页面隐藏后获得假通过。不同布局比例不得强行拉伸匹配。

首套原生截图经过逐屏审阅后可成为后续原生回归baseline，但不能把第一套明显比参考简单的界面直接批准为新目标。
