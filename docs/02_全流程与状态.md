# 02 · 用户流程、页面与状态

## 1. 导航结构

保持参考图的五个稳定入口：今天、地图、计划、地点、设置。紧凑布局用系统Tab；宽屏可用侧栏+内容但保留导航语义。一个共享选择模型保存地点、目的地日期、日内时刻；地图切换不会重置计划草稿。

### 主要页面

| 页面 | 内容与主要操作 | 不可遗漏的状态 |
|---|---|---|
| O01 欢迎 | 光线规划价值、离线边界、开始；不要求账号 | 可直接跳过、VoiceOver顺序、大字体滚动 |
| O02 选地点 | 主动定位/搜索/手动/示例 | 定位拒绝、粗略定位、无法解析时区、搜索离线 |
| H01 今日 | 地点+目的地日期、日出/晚黄金/日落/晚蓝调、太阳位置、全日曲线 | 示例徽标、计算中、极昼/极夜、无事件、跨日刷新 |
| H02 事件详情 | 早晚窗口、定义、结束时刻、与日落关系 | 无该窗口、开始在昨日/结束在明日 |
| M01 地图 | 观察点、当前天体方向、日出/落线、底部时间轴 | 地图失败但保留数字；太阳低于地平线用虚线 |
| M02 地点/观察点 | 搜索、长按/移动选点、确认时区 | 准备离开未保存编辑、重复地点、日期变化 |

| P03 计划详情 | 地点、目标、到场/黄金/日落/蓝调里程碑、编辑复制删除 | 提醒拒绝/过去/失败、目的地时区醒目标明 |

| S04 帮助/隐私 | 本地说明、正式链接、版本、许可 | 未配网址是开发阻塞，禁止占位链接进入正式版 |
| B01 解锁 | 功能、动态价格、一次性说明、购买、恢复、关闭 | 请求失败/Pending/取消/成功/未验证/退款 |

## 2. 首次使用闭环

欢迎 → 不请求权限 → 用户选定位或手动地点 → 解析并确认目的地时区 → 展示今日光线 → 用户拖动时间并知道太阳在何方向。

用户拒绝定位：不重复弹窗轰炸；保留搜索和手动输入。首次使用示例点时必须标注“示例地点”，不能把示例鼓浪屿冒充用户所在位置。切换地区不改变曾授权的权限。

## 3. 首次规划与付费闭环

选择未来日期/保存计划 → 合理触发解锁页 → 明示一次性买断与真实价格 → 用户可关闭回到原草稿 → 已验证交易成功后恢复刚才操作。恢复购买后也回到原操作，不退回首页。

计划编辑要求暂存草稿；购买页出现时不销毁草稿。未保存离开给“继续编辑/放弃更改”选择；不要将取消购买等同于放弃计划。

## 4. 保存与提醒必须分离

点击保存 → 校验目标在选定民用日存在 → 原子写入数据 → 展示已保存 → 用户启用提醒才申请通知权限 → 尝试安排 → 在计划上记录状态。

状态机：`disabled` / `notRequested` / `authorizedPendingSchedule` / `scheduled` / `denied` / `past` / `failed`。不存在“保存失败但通知已经安排”的流程。每个计划使用稳定通知ID；编辑先安全提交新数据，再用同ID替换安排；若重排失败，显示计划已更新但提醒失败。

提前时间以目标事件为基准；准备时间和提醒提前量两个独立字段，不能混为“导航路程”。目的地在UTC+9、手机在UTC-4时仍以同一个绝对瞬间提醒。

## 5. 返回、恢复与长时间后台

展开/折叠、旋转、分屏：保持地图中心、选点、天体、日期、时间轴、焦点及未保存文本。允许根据可用宽度更换结构，不能重建整个业务状态。

进入前台：若处于“今天跟随”模式且目的地跨了午夜，更新民用日；若用户正在规划指定日期，保持日期，不跳回今天。系统时钟或时区变化后重新校验，但不要把目的地时区替换为设备时区。

## 6. 例外处理

没有日落≠错误；“当天无日落事件”是合法结果。没有日出≠整天极夜，要判断太阳最高/最低高度。高纬度可能没有完整黄金/蓝调窗口，按实际区间展示，不补齐固定分钟数。

网络不可用：离线计算照常，地图/搜索说明需要连接。大数据文件：先验证大小再解码；不在主线程做大量解析。存储损坏：进入只读恢复模式，保留原文件并允许原样导出，不能重置为空白来掩盖问题。

导入文件预览：显示条目数、版本、重复项、被拒原因，默认合并且不静默覆盖。用户确认后原子替换并保留本地回滚备份；失败则恢复原数据。导入后的提醒不能在用户不知情时全部自动开启。
