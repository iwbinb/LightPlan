# Duo与宽屏工作台

Apple官方产品页已能核实Duo产品方向；具体可用SDK、模拟器逻辑尺寸、安全区和设备行为以Codex接手Mac上的工具链为准。不得把本包1024×820浏览器参考称为Duo真实分辨率或Duo实机截图。

实现使用容器可用宽度，绝不按机型字符串创建第二套App。当前参考分界760pt；是否在正式Duo展开窗口出现宽布局，要使用实际size class/可用宽度验证并调整断点。若实际窗口不足此宽度，应按内容可容纳性调整，不是维持760而声称“已适配”。

## 状态与布局

- 紧凑：单地图+底部控制面板；所有功能仍可用。
- 宽屏：地图位于HStack第一个稳定位置；右侧约33%、290–380pt的信息侧栏；完整时间轴在底部跨全宽。
- iPad使用同一布局，再根据窗口大小变化；支持多窗口尺寸变化的测试不等于已支持多用户协作。
- 最大辅助字号回到单列可滚动阅读，不强行塞两列。

共享状态：拍摄地点、目的地日期、selectedInstant、选中天体、地图相机、未保存计划。宽度改变不能创建新的AppState，也不能因为Map重新挂载而重置center/zoom。源代码保持Map位于同一结构位置；这一点仍须通过原生实际折叠/旋转操作验证。

## 设备证据

`capture_native.sh phone`针对现有普通iPhone；`expanded`选择现有iPad；`duo`只选择名字实际包含Duo的已安装模拟器。不存在就退出，不用iPad截图冒充Duo。

旋转连贯测试已有XCUITest入口，但旋转不等于折叠。真实Duo折叠、展开、中途切App、返回、权限弹层和键盘显示仍作为单独发布门槛。用户不需手动设计设备界面；Codex需要在本机SDK/设备环境中完成验证。
