# 04 · 天文、时间、坐标与精度

## 1. 统一定义

坐标输入用WGS84纬经度（十进制度），纬度[-90,90]、经度[-180,180]。方位角从**真北**顺时针计0..360°；高度角以观察者水平地平面为0°，上方为正。默认海平面观察者，无地形遮挡。磁北指南针不是同一个参考轴。

太阳/月亮位置以天体中心表示；`altitude`是几何高度，`apparentAltitude`另给名义折射近似。不可把两者混用定义蓝调/黄金窗口。参见 [S08]、[S09]、[S10]。

| 光线band | 太阳中心几何高度h |
|---|---|
| 夜间 | h < -18° |
| 天文暮光 | -18° ≤ h < -12° |
| 航海暮光 | -12° ≤ h < -6° |
| 蓝调 | -6° ≤ h < -4° |
| 黄金 | -4° ≤ h ≤ +6° |
| 日间 | h > +6° |

这是本产品统一采用的摄影时间窗定义，不是所有摄影App一致的自然法则。允许在帮助页解释，不在首页暗示一个固定时长。

日出/日落：名义太阳中心几何高度约-0.833°穿越水平地平线，合并名义折射和太阳视半径；气压、温度、观察高度、山丘建筑都会改变实际可见时刻。[S08] 特别提醒折射影响并说明NOAA旧计算器已不再维护。我们的App不调用该旧服务。

晚间次序应为：+6°进入黄金 → 名义日落(-0.833°) → -4°黄金结束/蓝调开始 → -6°蓝调结束。因此**日落不等于蓝调立即开始**。旧参考图不满足该统一定义，禁止将图中文字当测试预期。

## 2. 核心实现与验证

`Astronomy.swift` 保持 Foundation-only、完全离线。太阳使用 VSOP87D 地球周期项，经 FK5 修正、光行差、IAU 1980 章动、TT−UT 和视恒星时得到站心几何位置；月亮继续使用轨道元素/周期扰动近似与 WGS84 观察者视差。太阳数学与数据来自 MIT 许可的 astronomia，固定提交 `71e16c942b143a1a5a067b6aab2d8532064704ae`；版权和完整许可见 `licenses/astronomia-MIT.txt`。不把用于对照的 Swiss Ephemeris 代码或二进制加入 App。

太阳表由 `scripts/generate_solar_coefficients.py` 可重复生成，共保留 470 项 VSOP 系数及 63 项章动。省略规则是系数绝对幅度的数学上界，不是按测试样本拟合：整个支持范围（含 UTC 缓冲日）`|tau| < 0.102`，相对完整表的黄经/黄纬各自总省略上界小于 `1e-6` 弧度，距离上界小于 `1e-6` AU。此界只约束**表项精简误差**，不代表总星历、折射或实际可见时刻的精度。

TT−UT 使用 NASA Espenak/Meeus 分段多项式。未来地球自转不可预先精确获知，这部分是预测，不是已经量测的未来时间。[NASA 公式](https://eclipse.gsfc.nasa.gov/SEcat5/deltatpoly.html)

原有位置 QA 范围为 18 个全球/高纬地点 × 11 个离散时刻，共 396 组（太阳/月亮各 198 组，抽样覆盖 1900..2100）。2026-09-22 使用同一批坐标/时刻重新运行独立 Swiss Ephemeris 2.10.03 Moshier 站心位置对照，太阳最大天球角距离误差 **0.000878°**（此前简化模型记录约 0.009697°），月亮 **0.062524°**；未改变原验收阈值 0.08°/0.30°。记录见 `tests/reports/astronomy-events-2026-09-22-positions.json`。天顶附近按天球角距离比较，避免方位角本身病态放大。

这是有限样本结果，**不是 1900..2100 全时刻、全球连续保证**。原冻结位置参考继续进入 XCTest；独立参考工具不进入正常构建。缺少工具时必须明确失败，不能跳过后声称对照通过。

## 3. 事件搜索与独立验证

整日搜索以太阳 60 秒、月亮 120 秒为基础网格，额外精化局部极值，避免短暂高纬穿越只凭网格符号遗漏；发现穿越后将数值根精化至约 0.1 秒。**求根数值精度不是实际日出时间准确度**。

升落使用可变视半径与固定 34 角分的名义地平折射；摄影时间窗仍采用上表的太阳中心几何高度。对照使用 Swiss Ephemeris 自身的独立 `swe_rise_trans_true_hor` 升落求解器，上缘模式、关闭其可变大气折射并将几何地平设为 −34′，以匹配本产品的固定折射约定。蓝调/黄金/暮光以天体中心穿越指定高度独立求解，绝不把本引擎的高度残差作为外部预期。[独立参考接口](https://www.astro.com/swisseph/swephprg.htm)

2026-09-22 共验证 **31 个目的地民用日**，包括 23/25 小时 DST、Lord Howe 的 23.5/24.5 小时 DST、四分之一小时时区、国际日期变更线、1900/2100 两端、极昼/极夜及近相切案例。最终 **31/31 通过**；匹配的 305 个太阳事件最大时间差 **14.562 秒**，43 个月亮事件最大 **22.625 秒**，无漏报或多报事件。采用原文档目标：太阳 ≤60 秒、月亮 ≤120 秒，未为高纬单独放宽。

本次修复前真实失败也保留：北纬 67.398°、东经 13.8875°、2026-12-21 原模型遗漏短暂升落；北纬 89°、2026-03-20 的日落偏差 164.265 秒。原因是近相切几何将简化位置模型的小误差放大，进一步收紧二分求根不能修复位置模型。

证据与重跑入口：

- `tests/reports/astronomy-events-2026-09-22.md/.json`：最终独立事件对照、模型定义、逐项结果及源码摘要。
- `tests/reports/astronomy-events-2026-09-22-baseline.md/.json`：修复前失败，不删除。
- `tests/reports/astronomy-events-2026-09-22-full-vsop.md/.json`：完整系数中间验证，便于审查精简影响。
- `scripts/validate_astronomy_events.py`：需独立参考工具，任何时间/事件数量不匹配均非零退出。
- `Fixtures/astronomy-events.json` 与 `AstronomyEventReferenceTests.swift`：冻结独立数值，可在普通核心测试中离线重跑全部 31 日。

这些测试不覆盖现场气压、温度、海拔、山丘建筑遮挡，也不证明任意相切点都满足固定秒级目标。近地平/高纬精确拍摄仍应现场确认。

性能另行测量：本机 arm64 macOS Release 下 50 次独立进程的启动、整日计算、JSON 输出及退出合计 P95 约 **14.27 毫秒**，详见 `tests/reports/astronomy-events-2026-09-22-performance.json`。该结果不能替代最低支持 iPhone 的性能/能耗验收。

事件输出按绝对时刻排序，属于目的地日区间 `[start,end)`。相邻日边界不得重复，窗口取真实交集，不强制同时有早晚黄金。

## 4. 时间与日历

Place必须携带IANA时区ID，如Asia/Shanghai、Europe/Berlin。用`Calendar(identifier:.gregorian)`加目的地时区获取民用日区间；DST日可能23/25小时，Lord Howe可能23.5/24.5小时。已含相关单元测试。[S11]

语言Locale只影响文字、数字和日期显示，不能决定时区。内部绝对时刻用Date；备份用ISO8601；计划保存目的地时区快照，不能只存“17:30”或UTC偏移。显示日期与时间时始终携带目的地区域说明。

系统本地化日历可能显示泰国佛历，必须在用户界面与Gregorian计算年份之间正确转换，不能把佛历2569直接喂给天文算法。首发UI可明确使用公历日期并允许系统数字/格式；须在泰语QA中单独确认。

支持范围1900..2100是产品范围；日期边界需要按整个目的地民用日验证。接近最小/最大UTC边界的地点可能跨入前/后年，正式版必须加缓冲计算区或缩紧DatePicker有效日。日期异常必须可恢复，不能崩溃。

## 5. 摄影与几何解释

地图线从观察点**指向天体**；实际入射光方向相反。日出/日落线也以同一观察点起算，不是太阳在地图上的地理位置。

只有当用户提供镜头朝向（相机→被摄体方位）时，才可依据太阳与镜头方向夹角说明顺光/侧光/逆光倾向。不能仅凭“西南243°”说当前为柔和侧光。初版UI未提供朝向输入时，显示中性的太阳方向，不生成这类结论。

平地竖杆理想影长可用h/tan(太阳高度)，但高度接近0°敏感；这个公式不是楼宇三维阴影能力。V1不绘制未掌握高度/地形的建筑阴影，不把海岸线本身的图像误认为可用地形模型。

## 6. 地图一致性与精度提示

中国大陆等地区MapKit的地图显示与底层坐标关系须在实机用已知点验证，不能手写未经验证的GCJ转换后反复偏移；存储使用一致的坐标契约，系统API间转换遵循官方接口与当地服务条件。[S04]

允许无地图时看数值；缓存地图由平台管理，不能承诺所有地区全离线。方位数值并不保证手机指南针精度，附近金属、磁场和校准状态需要独立处理。地图真北默认无设备姿态依赖。
