# 02 · 用户流程、页面与状态

## 1. 导航结构

保持参考图的五个稳定入口：今天、地图、计划、地点、设置。紧凑布局用系统Tab；宽屏可用侧栏+内容但保留导航语义。一个共享选择模型保存地点、目的地日期、日内时刻；地图切换不会重置计划草稿。

## 2. 首次使用闭环

欢迎 → 不请求权限 → 用户选定位或手动地点 → 解析并确认目的地时区 → 展示今日光线 → 用户拖动时间并知道太阳在何方向。

用户拒绝定位：不重复弹窗轰炸；保留搜索和手动输入。首次使用示例点时必须标注“示例地点”，不能把示例鼓浪屿冒充用户所在位置。切换地区不改变曾授权的权限。

## 3. 付费下载后的首次规划

用户在App Store购买并下载应用 → 首次启动直接使用全部功能 → 选择未来日期/构图条件 → 搜索机会或推荐机位 → 确认时刻并保存计划 → 添加备注、查看或分享现场简报。应用内没有购买步骤，不等待商品请求，也不把完整功能藏在付费墙后。

计划编辑要求暂存草稿；未保存离开给“继续编辑/放弃更改”选择。分享简报会包含观察点/主体坐标、时刻、时区及用户备注，分享前明确提示，由用户自行选择接收方。重新下载应用不等同恢复本地计划，跨设备需主动导出/导入备份。

### 从模板到现场的具体流程

首页选太阳或月亮任务 → 地图选观察点与主体 → 确认默认天体和条件 → 搜索机会。太阳模板预设14日、天体高度0–6°和≤3°方位误差；月亮模板预设30日、0–20°、≤3°和80–100%照明。模板提供起步条件；清晨/傍晚、机位可达性和实际遮挡仍由用户确认。

机会列表顶部显示可横向滚动的完整条件预设。打开搜索选项后，日期和条件只修改草稿；“应用搜索”才触发后台计算，“取消”保留原查询。切换条件、关闭页面会取消工作；过时结果不能覆盖新查询。日数按目的地日历计算，遇支持范围末端显示实际搜索到的日期；最多显示60段匹配，并说明被截断的是结果数量。选择结果将**该窗内的最佳时刻**带回地图，不把整个时间窗误存为一个保证可见的持续事件。

在构图预演中调整等效焦距、横竖画幅、参考仰角和时刻 → 应用回地图 → 保存计划及可选项目名/备注。计划保留相机参数，详情可回看示意图并恢复地图。相机预演与机会搜索使用同一观察点/主体和绝对时刻；改变时刻后不沿用已经失效的匹配结论。

### M3 的时刻与草稿规则

构图面板按机位、主体、查找窗口、预演、保存排列主要操作；当天最佳时刻是建议，只有主动选择后才移动地图。预演和保存始终使用地图当前绝对时刻，手动步进或拖动后不能偷偷换回当天最佳值。低于地平线仍明确提示，不把几何计划当作可见性保证。

已应用的搜索起始日、日数、条件（包括“全部”）及排序仅保存在当前应用会话中，太阳与月亮分开、各最多一份。关闭搜索或切换 Tab 后重新打开保留输入，但结果重新计算；排序本身不重算。修改机位/主体/偏移或主动换地图日期时，保留该天体的条件和日数、将起始日切到新地图日。选择某个搜索结果只移动地图，不改变原先完整搜索范围。显式模板和已保存计划的条件优先，重置该天体的搜索记忆。退出进程不承诺恢复这份会话记忆，备份格式不变。

搜索中可停止，显示“已停止”而不是空结果，并可用原输入重新搜索。无匹配和计算失败分开显示；用户可直接打开原条件修改。放宽为“全部候选”必须由用户点击，不静默降低条件。选项里的未应用修改仍可取消，不改变当前查询。

计划编辑器冻结其机位快照；文本、日期、项目和相机参数在旋转、嵌套预演返回和选择“继续编辑”时不重置。未修改的编辑器可直接关闭，有修改时取消必须明确选择继续或放弃，交互下拉不丢弃草稿。保存失败保留原输入，过时预览不能启用保存。

计划列表可用多个关键词匹配名称、地点、备注与项目，并按状态筛选。进入现场模式，倒计时先到到场时刻，再到拍摄时刻；过后显示已过，不把过去时间继续倒数。标记完成先保存状态再取消该计划的待发通知；失败应显示错误而非成功。恢复待拍保留计划、项目和相机参数，但提醒需用户重新开启。已完成且无当天事件的历史计划仍可查看保存记录，不虚构事件时刻。

## 4. 保存与提醒必须分离

点击保存 → 校验目标在选定民用日存在 → 原子写入数据 → 展示已保存 → 用户启用提醒才申请通知权限 → 尝试安排 → 在计划上记录状态。

状态机：`disabled` / `notRequested` / `authorizedPendingSchedule` / `scheduled` / `denied` / `past` / `failed`。不存在“保存失败但通知已经安排”的流程。每个计划使用稳定通知ID；编辑先安全提交新数据，再用同ID替换安排；若重排失败，显示计划已更新但提醒失败。

完成状态也是提醒资格的一部分：已完成计划即使旧备份仍带提醒提前量，也不应重新排入通知队列。恢复待拍与复制计划均不自动恢复旧提醒；复制另获新ID，清除完成状态。

提前时间以目标事件为基准；准备时间和提醒提前量两个独立字段，不能混为“导航路程”。目的地在UTC+9、手机在UTC-4时仍以同一个绝对瞬间提醒。

## 5. 返回、恢复与长时间后台

展开/折叠、旋转、分屏：保持地图中心、选点、天体、日期、时间轴、焦点及未保存文本。允许根据可用宽度更换结构，不能重建整个业务状态。

进入前台：若处于“今天跟随”模式且目的地跨了午夜，更新民用日；若用户正在规划指定日期，保持日期，不跳回今天。系统时钟或时区变化后重新校验，但不要把目的地时区替换为设备时区。

## 6. 例外处理

没有日落≠错误；“当天无日落事件”是合法结果。没有日出≠整天极夜，要判断太阳最高/最低高度。高纬度可能没有完整黄金/蓝调窗口，按实际区间展示，不补齐固定分钟数。

网络不可用：离线计算照常，地图/搜索说明需要连接。大数据文件：先验证大小再解码；不在主线程做大量解析。存储损坏：进入只读恢复模式，保留原文件并允许原样导出，不能重置为空白来掩盖问题。

导入文件预览：显示条目数、版本、重复项、被拒原因，默认合并且不静默覆盖。用户确认后原子替换并保留本地回滚备份；失败则恢复原数据。导入后的提醒不能在用户不知情时全部自动开启。
