# 11 · Cloudflare静态站与部署边界

## 当前选择

App核心无账号、无后端、无D1/R2/KV/Queue需求。使用Cloudflare Pages承载展示、支持和隐私政策即可。避免为每个用户创建服务端档案或持续上传位置。静态站参考官方部署文档。[S15]

`site/`已提供可部署的静态草案。正式部署前填入经所有者确认的产品主体、支持邮箱与正式域名，审查隐私说明与当前二进制一致。当前包**没有部署、没有创建任何Cloudflare资源**。

## 本地预览

```
python3 -m http.server 8080 --directory site
```

用浏览器检查首页、支持、隐私、手机布局和无效链接。没有第三方追踪脚本、不请求定位、不加载广告。确认域名后将正式URL配置到iOS设置页和App Store Connect。

## 部署路径

Codex在得到账号授权后，先检查当前Cloudflare项目是否存在，优先复用已授权项目。可按官方Pages Direct Upload或Git集成发布静态目录；所需CLI版本、认证方式以本机/官方最新文档为准，不把token放到命令历史、源代码或ZIP。

示意命令（须在确认授权并安装当前兼容Wrangler后执行）：
```
npx wrangler pages deploy site --project-name lightplan
```

此命令可能创建/修改远端部署，本包脚本不会自动执行。未授权不部署。域名已被使用或项目不存在时不能假设拥有它；也不能写“上线成功”而不给实际URL与HTTP检查证据。

## 发布检查

HTTPS访问、重定向、隐私/支持链接、移动端、邮件地址可用、没有占位符、无PII采集、无破损路径。若未来加入联系表单/邮件投递/分析，要先新增数据清单、保留周期、防滥用和成本上限，再决定Workers或第三方服务。
